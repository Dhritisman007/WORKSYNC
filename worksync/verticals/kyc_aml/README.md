# KYC/AML vertical

Data: **entirely synthetic**, generated by `data_gen.py` (seed `4242`,
`numpy.random.default_rng`). No real applicants, no real PEP list, no real
sanctions list — the names, scores and the `high_risk_label` target are all
fabricated for this project.

## Pipeline

1. `data_gen.py` — generates `applicants.csv` (5,000 rows), `pep_list.csv`
   and `sanctions_list.csv` into `worksync/data/raw/kyc_aml/` (gitignored —
   regenerate with `python -m worksync.verticals.kyc_aml.data_gen`).
   Deterministic: same seed, same output (see `test_data_generator_is_deterministic`).
   A small fraction of applicants are deliberately given a name that matches
   the PEP/sanctions lists, so the screening rules have real hits to catch.
2. `adapter.py` — maps an applicant row to `CaseRecord`, same shared-
   feature-engineering pattern as the loan vertical.
3. `model/train.py` / `model/risk_model.py` — LightGBM (primary,
   calibrated) + XGBoost (baseline) trained against the synthetic
   `high_risk_label`. **This label is a documented function of the same
   risk signals plus noise, not a real fraud outcome** — treat the model's
   metrics (`docs/kyc_aml_model_report.md`) as a pipeline-correctness check,
   not a claim about real-world detection performance.
4. `rules.yaml` — sanctions match (hard reject), PEP match (hard escalate —
   enhanced due diligence), poor document quality (hard escalate), adverse
   media hit (soft), application velocity spike (soft). **All
   `verified: false`**, no invented clause numbers.
5. `manager_config.yaml` — same grey-band shape as loan, tuned thresholds.
6. `run_samples.py` — runs N applicants end to end, deliberately forcing in
   at least one sanctions hit and one PEP hit so the demo actually shows
   those rules firing.

## Regenerating

```bash
python -m worksync.verticals.kyc_aml.data_gen
python -m worksync.verticals.kyc_aml.model.train
python -m worksync.verticals.kyc_aml.run_samples 20
```

## Why the model is somewhat redundant with the rules here

Sanctions/PEP matches are always hard flags that override the model's score
via the Manager Agent's fixed precedence — the model can't approve past a
sanctions hit no matter what it predicts. Its job is the residual risk: a
case that clears screening but still has weak signals (bad document scan,
high device risk, velocity spike) that a pure rules engine wouldn't catch
on its own.
